The rule to remember: a query passes connect, parse, names, plan, run, memory. Typos fail at parse. Wrong names fail at names. Bad math fails at run. A write adds the log: it must reach the disk before the pages do.

    
Words on this page:

    
    
      
  • Backend process: the helper Postgres starts for each connection.
    • 
      
  • Planner: picks the cheapest way to run the query, using a score called cost.
    • 
      
  • Executor: the part that really reads and changes rows.
    • 
      
  • Shared buffers: the memory area where recently used 8 KB pages wait.
    • 
      
  • WAL (write-ahead log): the log of changes. After a crash Postgres replays it.
