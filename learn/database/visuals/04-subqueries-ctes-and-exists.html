The rule to remember: a plain subquery runs once. A correlated subquery uses the outer row, so think of it as running once per outer row. EXISTS stops at the first match. A store with no match is the expensive one: Postgres must read everything to be sure. NOT IN breaks when the list holds a NULL, because every check against NULL is unknown. NOT EXISTS only asks "is there a matching row?", so it is always yes or no.
