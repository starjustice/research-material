The rule to remember: a row lock stops other writers of that row until the transaction ends. It does not stop readers. A deadlock is a circle of waits, and Postgres breaks it by cancelling one transaction.

    
Words on this page:

    
    
      
  • Row lock: held by a transaction that changed a row (or used FOR UPDATE), until COMMIT or ROLLBACK.
    • 
      
  • Deadlock: A waits for B and B waits for A. Error code 40P01. Run the cancelled transaction again.
    • 
      
  • lock_timeout: give up waiting for a lock after a set time.
    • 
      
  • ACCESS EXCLUSIVE: the strongest table lock. Most ALTER TABLE statements take it. It conflicts with everything, even a SELECT.
