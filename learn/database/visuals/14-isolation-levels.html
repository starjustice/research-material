The rule to remember: READ COMMITTED takes a new picture for every statement. REPEATABLE READ takes one picture per transaction. SERIALIZABLE cancels a transaction when the result could not come from running them one at a time.

    
Words on this page:

    
    
      
  • Non-repeatable read: the same row read twice gives two answers in one transaction.
    • 
      
  • Write skew: two transactions read the same rows and each write a different row, and together they break a rule.
    • 
      
  • Serialization failure (40001): Postgres cancelled the transaction on purpose. Run it again.
    • 
      
  • A and B: two sessions (two psql windows, or two connections).
