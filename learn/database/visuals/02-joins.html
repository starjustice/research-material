The rule to remember: ON decides which rows match. A LEFT JOIN keeps every left row, and fills NULL when nothing matched. WHERE runs after the join and throws rows away. NULL = 'PAID' is never true, so a WHERE on the right table throws away the NULL rows the LEFT JOIN just kept.

    
How to read the colors:
      yellow is the row Postgres is working on.
      green is a match, or a new result row.
      orange is the right store but it fails the rest of the ON rule.
      red is a row nobody matched, or a row WHERE throws away.
      Gray rows did not match.

    
Words on this page: join: glue a row from one table to a row from another table when they match. match rule: the part after ON (interview word: join condition). NULL: an empty cell, "no value here". outer join: the interview name for LEFT, RIGHT and FULL, the joins that keep rows with no match.

    
This page shows the idea: each row looks for its matches. Real Postgres may use a faster method (lesson 11), but it always gives the same rows. Without ORDER BY, Postgres does not promise any row order. Every result here comes from a real run on PostgreSQL 18.3 on 2026-10-16.
