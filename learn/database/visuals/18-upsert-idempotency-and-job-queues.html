The rule to remember: things arrive twice. Let a unique key decide who goes first (ON CONFLICT), do the marker and the work in one transaction, and let queue workers use SKIP LOCKED.

    
Words on this page:

    
    
      
  • Idempotent: running it twice gives the same result as running it once.
    • 
      
  • ON CONFLICT DO NOTHING: insert, or quietly skip if the unique value exists (INSERT 0 0).
    • 
      
  • FOR UPDATE: lock the rows the SELECT returns until the transaction ends.
    • 
      
  • SKIP LOCKED: leave out rows that another transaction has locked, so you never wait.
