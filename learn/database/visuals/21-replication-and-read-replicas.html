The rule to remember: a replica is a read-only copy that is a little behind. A user may not see their own write there. After a write, read from the primary or wait for the replica to catch up.

    
Words on this page:

    
    
      
  • WAL / LSN: the write-ahead log, and a position in it. The replica replays the log.
    • 
      
  • Replication lag: how far the replica is behind. Measure it with replay_lag on the primary.
    • 
      
  • Asynchronous / synchronous: the primary does not wait for the replica / it waits for it before it answers COMMIT.
    • 
      
  • Failover: promote a replica to be the new primary.
