The rule to remember: a transaction is all or nothing. Other sessions see the old values until COMMIT, then they see all the new values at once.

    
Words on this page:

    
    
      
  • BEGIN / COMMIT / ROLLBACK: start the transaction, keep all of it, throw all of it away.
    • 
      
  • Aborted: after an error, the transaction refuses every statement until it ends. COMMIT then answers ROLLBACK.
    • 
      
  • Write-ahead log (WAL): the file where Postgres writes every change first. COMMIT waits for it to reach the disk.
    • 
      
  • Recovery: after a crash, Postgres replays the log: committed work stays, unfinished work is dropped.
