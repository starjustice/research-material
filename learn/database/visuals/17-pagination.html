The rule to remember: OFFSET reads and throws away every skipped row, so deep pages are slow and shift when data changes. Keyset says after this row, and the index jumps straight there.

    
Words on this page:

    
    
      
  • OFFSET: skip N rows. LIMIT: then take M rows.
    • 
      
  • Keyset (seek) pagination: filter with the last row you saw, then LIMIT.
    • 
      
  • Cursor: the last row (created_at and id) packed into one value the client sends back.
    • 
      
  • Tie-breaker: the unique id at the end of the ORDER BY, so two rows are never equal.
