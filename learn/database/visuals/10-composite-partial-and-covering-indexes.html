The rule to remember: an index on (store_id, created_at) is sorted by store first, then by date inside each store, like a phone book sorted by last name, then first name. Postgres can jump only to a value of the first column. After the jump it reads entries in order and can stop early. A partial index holds only the rows you care about. A covering index carries extra values, so Postgres does not need to visit the table.

    
Words on this page:

    
    
      
  • Index entry: one line in the index: the key values plus a pointer to the row in the table.
    • 
      
  • Jump: Postgres walks down the index tree to the first matching entry. EXPLAIN on Postgres 18 counts these as Index Searches.
    • 
      
  • Table visit: Postgres follows the pointer to read the full row from the table. EXPLAIN calls a visit during an Index Only Scan a Heap Fetch. (Heap is the Postgres word for the table itself.)
    • 
      
  • Composite index (multicolumn index): one index on two or more columns.
    • 
      
  • Skip scan: new in Postgres 18. When the first column has only a few different values, Postgres can jump once per value instead of reading the whole index.
