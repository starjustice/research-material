1 · How long one round trip takes

Say this: "Same zone calls are under a millisecond, across the world is 150 ms or more. So I count round trips on the user's path and keep chatty parts close together."

2 · Reuse connections: setup is paid once

Say this: "A new HTTPS connection costs about two round trips before any work. I reuse connections with keep-alive and share database connections through a pool sized from the database limit."

3 · DNS failover waits for the TTL

Say this: "DNS failover is only as fast as the TTL, and some clients keep answers longer. For fast failover I use a global load balancer with a fixed anycast IP."

4 · Four ways for the server to tell the client

Say this: "I pick the simplest option that fits: SSE when only the server talks, WebSockets when both sides talk often, and push notifications when the phone app is closed."

5 · Scaling WebSockets with pub/sub fan out

Say this: "Each WebSocket server subscribes to the rooms of its own users. A message is published once to Redis, and every server that holds a member pushes it on."

6 · AWS layout for Express and Postgres

Say this: "Only the load balancer sits in public subnets. App and database are private across two zones. Security groups chain load balancer to app to database, so nothing else can reach Postgres."

7 · Timeouts shrink inward, retries multiply

Say this: "Every call gets a timeout, shorter on the inside. I retry at one layer only, with backoff and jitter, and only for idempotent calls, because retries at every layer turn one click into 27 calls."

Round trip rules of thumb (2026)

TripRound tripDesign meaning
Same machinewell under 0.1 msalmost free
Same data center or zone0.1 to 0.5 ms100 database calls is still fast
Across zones in one region1 to 2 msAWS: single digit ms, zones within about 100 km
Same continent10 to 50 msusers feel many trips
Across the world150 ms or moreCDN, fewer trips, maybe a nearer region
New HTTPS connectionabout 2 round tripsreuse connections
