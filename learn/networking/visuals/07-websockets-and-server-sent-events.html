WebSockets and server sent events: how a server talks first

Use the buttons below to move one step at a time. Guess first, then check. This is a small model of the practice answer (parseSse, formatSse, missedEvents, acceptKey, handshake, encodeFrame, decodeFrame, backoffDelay, chooseTransport, deliver). No real network or browser is used here.

setup

The rule to remember: plain HTTP cannot push. Polling asks again and again. SSE is one long answer, one way, and the browser reconnects for you. A WebSocket is a two way connection after a 101 handshake, and you write the reconnect and the Origin check. Many servers need pub/sub to share messages.
