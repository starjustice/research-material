TLS and HTTPS: key exchange, the handshake, what a spy sees, forward secrecy, resumption, mTLS

Use the buttons below to move one step at a time. Guess first, then check. This is a small model of a TLS 1.3 connection. The numbers in the key exchange are tiny so you can follow them by hand. It runs the same modPow, dhPublic, validateHandshake, whatObserverSees, canReadRecordedTraffic, acceptEarlyData and checkClientCert code as the practice answer in the lesson. The rule to remember: a key exchange lets two strangers make the same secret while a spy watches. The handshake uses it, proves who the server is, and then everything is encrypted. A spy still sees the IP, the server name (until ECH), the sizes and the timing. A throwaway key gives forward secrecy. A ticket speeds up the next visit, and early data can be replayed. mTLS makes the client show a certificate too.
