Use the buttons below to move one step at a time. Guess first, then check. This is a small model of how a resolver works. It runs the same createResolver, followCname, wildcardLookup, validateZone, earliestSafeMove, pickWeighted and recordTypeFor code as the practice answer in the lesson. Nothing here talks to the real internet. The names and addresses are made up (the example ranges 203.0.113.x and 198.51.100.x are reserved for documents). Real dig output is in the lesson.

setup

The rule to remember: the resolver asks root, then .com, then the domain's own server, and each one only points to the next. The answer is saved for its TTL. A change is not seen until every saved copy runs out. A CNAME is another name for a name, and it cannot share a name with other records, so the apex needs an alias or an A record.
