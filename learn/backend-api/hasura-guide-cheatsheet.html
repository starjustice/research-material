Where Hasura sits

Say this: "Hasura compiles GraphQL into one SQL query with the role's permissions baked in — CRUD needs no code. Anything custom goes out the side: Actions call my Node service, event triggers push row changes to webhooks."

The CLI keeps every console click in git. Dev = console via CLI; prod = apply only.

CommandWhat it does
hasura init myappNew project folder: metadata/ + migrations/
hasura consoleOpen the console THROUGH the CLI — clicks become local files you commit
hasura metadata exportPull the server's config into local files
hasura metadata applyPush local config to a server (CI/CD step)
hasura migrate create add_todosNew SQL migration
hasura migrate applyRun migrations (CI/CD step)
hasura metadata diffWhat differs between local files and the server — drift detector

The permission rule to memorize

{ "user_id": { "_eq": "X-Hasura-User-Id" } }

→ role "user" can only ever touch rows where user_id = their session id.
→ Compiled into the SQL WHERE clause. Impossible to forget.

The JWT claims Hasura reads

"https://hasura.io/jwt/claims": {
  "x-hasura-default-role":  "user",
  "x-hasura-allowed-roles": ["user"],
  "x-hasura-user-id":       "42"
}

Both sides visible. The verdict line is your interview answer.
