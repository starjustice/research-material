BACKEND AND API CHEATSHEET

HTTP, REST and Express middleware on one page. See it, say it, remember it.

One card per lesson, in order. Read the rule, then tick ✓ when you can say it out loud without looking.

The pictures to draw on a whiteboard. Try to draw each one from memory in under one minute.

1 · A request and a response have the same four parts (lesson 01)

Only text travels. Only the first line is different.

Say this: "A request is a request line with the method and path, then Name: value headers, an empty line, and a body if there is one. A response has the same shape, but its first line holds the status code. The server always knows the method and path before it reads any body."

2 · Status codes: read the first digit (lesson 01)

Learn the five families first. Then single codes are easy.

Say this: "The first digit is the family. 2xx worked, 3xx look somewhere else, 4xx your request is wrong, 5xx the server broke. The most useful split is 4xx against 5xx: 4xx means change the request, 5xx means it is not your fault, maybe try later."

3 · 401 against 403: two questions, in order (lesson 01)

403 can only happen after question 1 passed.

Say this: "The server asks two questions in order. Who are you? If it cannot tell, that is 401, so log in. May you do this? If not, that is 403. A 403 means the server knows me and still says no, so sending the same token again does not help."

4 · REST: one noun, five methods (lesson 02)

The verb is the method, never a word in the path. The status tells the truth.

Say this: "I name the thing with a plural noun, like /orders, and the HTTP method is the verb. The id goes in the path, filters go in the query string, and I nest one level at most. Then any developer can guess the next URL without asking."

5 · Offset against cursor, when a new order arrives (lesson 02)

Page size 5. Budi saw page 1. Then order 31 arrives at the top. Now he asks for page 2.

Say this: "Offset counts places, so when a row is added or removed, every row below it moves and the next page shows one twice or skips one. A cursor is the id of the last item the app saw, so the server asks for ids below it, and it does not care where rows moved."

6 · The Express line, and the jump to the error middleware (lesson 03)

Each function fills something on req for the next one. An error skips every normal function.

Say this: "Express runs one line of functions in the order I added them: logger, express.json, auth, routes, a 404 catch-all, error middleware. They all share one req, so auth puts req.user there and the route reads it. If anything throws or calls next with an error, Express skips every normal function and jumps to the error middleware, which has four parameters and goes last."

7 · How one middleware can end: three are fine, two are bugs (lesson 03)

The rule: next or send, never neither, never both.

Say this: "Every middleware must do exactly one of three things: call next, send an answer with return, or pass an error with next(err). If it does neither, the request hangs. If it sends and then calls next, the route still runs, so a 401 can still create an order."
