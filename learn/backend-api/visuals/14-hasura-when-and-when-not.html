The rule to remember: let Hasura do the boring CRUD and the row filters. Keep rules about money, other services and many steps in your own code.
  
    
    
  • Permission rule: for one role, table and action: a row filter and a list of columns. It can use the user id from the token.
    • 
    
  • Session variable: a fact from the token, like x-hasura-user-id.
    • 
    
  • Action: an operation in the API whose code is your own server.
    • 
    
  • Event trigger: Hasura calls your webhook when a row changes. It delivers at least once.
    • 
  

  Remember: the admin role skips every rule, so test as the real role. The admin secret must never be in a client. API limits are on paid and Enterprise plans only.
