The rule to remember: use the simplest one that works: polling for rare news, SSE for one-way pushes, WebSocket when both sides talk. Connections drop, so plan for reconnects.
  
    
    
  • Polling: the client asks again and again, "anything new?"
    • 
    
  • SSE: the server keeps one HTTP answer open and pushes text events. One way.
    • 
    
  • WebSocket: one connection that stays open. Both sides can send at any time.
    • 
    
  • Heartbeat: a tiny message on a timer to show the line is alive (ping and pong for WebSocket).
    • 
  

  Codes to know: 101 = switching protocols (a WebSocket starts). 204 = tells an SSE client to stop reconnecting. WebSocket close codes: 1000 normal, 1006 the line died.
