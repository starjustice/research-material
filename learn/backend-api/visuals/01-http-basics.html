HTTP basics: the text that travels, 401 against 403, and fetch on a 404

Use the buttons below to move one step at a time. Watch Ana's app write the request, the text cross the wire, and the server read it part by part. Guess first, then check.

setup

The rule to remember: a request is plain text: a request line (method and path), header lines, an empty line, then the body. The answer starts with a status line, so read the status first. 2xx worked, 4xx your request is wrong, 5xx the server broke. 401 means "who are you?" and 403 means "I know you, and no". fetch does not throw on a 404 or a 500, so always check res.ok.
