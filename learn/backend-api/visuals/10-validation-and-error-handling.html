The rule to remember: never trust the input, never show the insides. Check at the door, answer every problem in one shape, and keep the details in the private log.
  
    
    
  • Validation: checking the input before your code uses it.
    • 
    
  • Schema: the written rule for good input, one line per field.
    • 
    
  • Error handler: one function at the end. Every error ends up there.
    • 
    
  • Problem Details: the standard error shape with type, title, status and detail (RFC 9457).
    • 
  

  Status codes: 400 = the request is broken. 422 = well formed, but the values are wrong. 409 = clashes with what exists. 500 = our bug or something unknown.
