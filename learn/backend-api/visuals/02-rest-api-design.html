REST API design: offset paging against cursor paging while the list changes

Use the buttons below to move one step at a time. Watch what the app has shown, the request the app sends, and the orders table. Guess first, then check.

setup

The rule to remember: offset paging says "skip 5 places". When a row is added or removed above, every row moves, so the app sees one row twice or never sees one. Cursor paging says "start after order 26". Rows added above the bookmark, or rows that leave the list, do not move it. Ask for one extra row to know has_more, and never send more than the limit.
