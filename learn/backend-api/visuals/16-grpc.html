The rule to remember: number every field and never reuse a number, always set a deadline, and expect gRPC status codes, not HTTP ones.
  
    
    
  • gRPC: calls between programs, as small binary messages over HTTP/2.
    • 
    
  • Protobuf: the .proto contract file and the binary format of the messages.
    • 
    
  • Deadline: the moment after which the caller stops waiting.
    • 
    
  • Stream: many messages on one call.
    • 
  

  Status codes (a few): 0 OK, 3 INVALID_ARGUMENT, 4 DEADLINE_EXCEEDED, 5 NOT_FOUND, 14 UNAVAILABLE (retry with backoff), 16 UNAUTHENTICATED. The HTTP status of a gRPC answer is 200 even for errors.
