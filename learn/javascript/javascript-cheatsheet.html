1 · Before line 1 runs: every name gets a slot (lesson 01)

The code does not move. Only the slots are made early, and each kind starts in a different state.

Say this: "Before running, JavaScript makes a slot for every name. A var slot starts as undefined. A let or const slot is locked until its line, so reading it early is a ReferenceError. A function declaration is ready at once. The code itself never moves."

2 · Copy a number, copy an arrow (lesson 03)

A slot holds a simple value, or an arrow to an object. = copies what is in the slot.

Say this: "JavaScript always copies the value in the slot. For an object, that value is an arrow, so two names can point at one object. Spread makes a new outer object only. The inner objects are still shared. For a full copy, use structuredClone."

3 · Each call gets a box, and a closure keeps it alive (lessons 04 and 05)

After both makeCounter() calls finish, the call stack is empty. The two boxes stay, because a and b still point at them.

Say this: "Every call makes a new scope box. A function keeps a link to the box where it was made, and a box stays alive while something points at it. So each counter remembers its own count after makeCounter has finished. That is a closure."

4 · Who is this? Ask in order, stop at the first yes (lesson 06)

Say this: "this is decided by the call, not by where the function is written. Arrow functions have no this of their own, they borrow it. For normal functions I check: new, then call/apply/bind, then a dot call, then a plain call."

5 · The chain of hidden links (lessons 07 and 08)

Reading walks right until it finds the name. Writing always stays on the first object.

Say this: "Every object has one hidden link. When I read a property the object does not own, JavaScript follows the links until it finds it, or gives undefined at null. A class sets up exactly this: methods live once on the prototype, and every instance links to it."

6 · map, filter, reduce: same input, three shapes (lesson 09)

Say this: "They do the loop for me. I write only the small function for one item. map and filter return a new array and never change the original. reduce carries a running total, and I always give it a start value."

7 · The event loop: two waiting lines (lesson 11)

Say this: "JavaScript has one call stack. Slow work waits in the browser. When the stack is empty, the event loop runs all the microtasks first, like promise callbacks, then takes one task, like a timer. So setTimeout 0 always runs after a resolved promise."
