Kubernetes objects: Deployment, pods, Service and Ingress, step by step

Use the buttons below to move one step at a time. Guess first, then check. There is no real cluster behind this page: it runs the same small model as the practice in the lesson, and the pod names and nodes are examples. Real pod names look like shop-api-<hash>-<random letters>.

setup

The rule to remember: you write what you want, and loops keep reality equal to it. A Deployment keeps the right number of pods. A Service sends traffic to ready pods that match its label. An Ingress needs a controller, and then it sends each request to a Service by host and path.
