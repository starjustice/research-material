CI/CD pipelines: stages, a failing test, the cache, and a way back

Use the buttons below to move one step at a time. Guess first, then check. The seconds come from real runs of a small pipeline script on one laptop (Docker Desktop 29.3.1, Node 24 alpine). Your times will differ. The GitHub notes in stories 2 and 3 are from the GitHub docs, not run here.

setup

The rule to remember: a pipeline runs the same stages on a clean machine for every push. A failed stage stops the line. Build once, tag it with the commit id, and deploy that exact build. Keep the old builds, so the way back is quick.
