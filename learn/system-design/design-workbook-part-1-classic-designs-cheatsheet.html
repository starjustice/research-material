DESIGN WORKBOOK, PART 1: SIX CLASSIC DESIGNS

Rate limiter · Chat · News feed · File upload · Autocomplete · Video streaming

One picture per design. Cover the "Say this" line, redraw the picture, then say it out loud.

1 · Rate limiter: the edge burst, and the token bucket that fixes it

Two numbers per client in Redis, changed by one Lua script, so many servers share one count.

Say this: "A token bucket per client in Redis: tokens left and last refill time. One Lua script reads, adds the refill, takes a token and writes, all in one step, so 20 servers cannot both take the last token. Fail open on normal routes, fail closed on login."

2 · Chat: save first, then deliver

"Sent" means "on disk". Everything after that can fail and the message is still safe.

Say this: "Connection servers hold WebSockets and a Redis map says who is where. I save the message, then ack the sender, then deliver. Offline users get a push only as a wake-up; the store is the truth, and phones sync from their last message id."

3 · News feed: fan out on write, on read, and the mix

Do the work when someone posts, or when someone reads. Big accounts break the first one.

Say this: "Fan out on write for normal accounts so feeds are ready in the cache. Accounts over a follower cut-off are fetched at read time and merged. Only post ids go in the cache, and a cursor stops new posts from shifting pages."

4 · File upload: two paths, small JSON and big bytes

The API checks and signs. The bytes go straight to object storage.

Say this: "The API only handles metadata and signs short-lived URLs. Bytes go straight to object storage in parts, so uploads resume. A storage event starts thumbnail work in a queue, and private downloads go through the CDN with signed URLs."

5 · Autocomplete: a fast loop that reads, a slow loop that builds

The data is small and changes slowly, so the answers are made ahead of time.

Say this: "I compute the top 10 for every prefix offline and serve it from memory, so each key press is one lookup. Debounce and caching cut requests, and each build is a new version that goes live only after a check."

6 · Video: a pipeline that makes qualities, a player that picks them

Slow work goes through a queue. The CDN serves plain files. The player decides.

Say this: "Upload with presigned parts, then a queue of chunk jobs turns one file into several qualities as short segments. The CDN serves plain files and the player switches quality per segment. View counts are batched so a viral video does not lock one row."

7 · Five questions that pick the building block

Ask these right after your estimation step.

Say this: "My numbers say the slow part is X, so the building block is Y. Here is what Y costs, and here is when I would pick something else."

Explain each out loud. Tick only when you can say it without looking.
