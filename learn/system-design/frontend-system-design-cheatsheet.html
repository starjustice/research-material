1 · RADIO in a 45 minute round

Say this: "I'll go requirements, parts, client data, API, then deep dives. I'll treat the server as a black box and spend most time on the client."

2 · Five homes for state (ask in this order)

Say this: "Most feed state is server data, so it goes in the query cache. Filters go in the URL. Small UI flags stay local. The global store holds only what is left."

3 · When the page shows, and when it works

Say this: "I pick rendering per page. Static for the same content, ISR when it changes, a static shell plus streamed parts for personal pages, and CSR for tools behind login."

4 · Optimistic update with rollback

Say this: "I change the cache first, keep a snapshot, and put it back if the server fails. Then I invalidate, so the screen ends with the true value."

5 · Real time: least power that works

Say this: "Polling for rare changes, SSE for one way live updates, WebSockets for chat. Reconnect with backoff and jitter, resume from the last id, and dedupe by id."

6 · Mobile: offline queue and old app versions

Say this: "The screen reads a local store, changes go to a saved queue with idempotency keys, and the API only adds fields, because old app versions stay in use for months."

7 · Where the auth token lives in the browser

Say this: "Tokens go in an httpOnly, Secure, SameSite cookie, not localStorage. I add a CSP against XSS and a CSRF token for risky forms."

Explain each out loud. Tick ✓ only when you can.
