SIX DESIGNS WHERE CORRECTNESS MATTERS

Seat booking · Wallet ledger · Loan workflow · Job scheduler · Nearby drivers · RAG assistant

First list what must never go wrong. Then name the database tool that keeps it true. Redraw each picture from memory.

1 · Seat booking: put the "is it free?" rule inside the UPDATE

Say this: "Two fans can read 'free' at the same moment. So I do not read and then write. One UPDATE checks the status in its WHERE. The row lock makes the second fan wait, and then they get zero rows."

2 · Wallet: double entry ledger, every transfer adds up to zero

Say this: "Money never appears or disappears: every transfer is two entries that add up to zero. Rows are only added, so any balance can be explained. The idempotency key is unique, so a retry cannot pay twice."

3 · Loan workflow: a state machine with maker checker

Say this: "The loan is a state machine. A move only happens if the row is still in the right state and version, and the checker is not the maker. The audit row is written in the same transaction, and the payout carries an idempotency key."

4 · Job scheduler: claim with SKIP LOCKED, and no exactly once

Say this: "Workers claim due runs with FOR UPDATE SKIP LOCKED, so they never wait on each other and never take the same row. A lease lets another worker take over after a crash. Nothing can promise exactly one runner, so I promise at least once and make jobs safe to repeat."

5 · Nearby drivers: cut the map into cells, search 9 cells

Say this: "Live locations change every 4 seconds, so they live in Redis GEO, one key per city. I search the rider's cell and its neighbors, because the closest driver may sit just across the edge. A SET NX lock makes sure a driver gets one offer at a time."

6 · RAG assistant: filter by permission inside the search

Say this: "I copy each document's allowed groups onto its chunks and filter inside the vector query, so secret text never reaches the model. Documents can carry prompt injection, so the model has no write tools and I block unknown links in answers."
