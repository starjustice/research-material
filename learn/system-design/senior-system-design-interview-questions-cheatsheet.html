SYSTEM DESIGN INTERVIEW DRILL

60 questions, beginner to senior · say it out loud first · then open the card

The four-part answer, every time

Every card has the same shape. Learn the shape once and fill it per question.

Say this: "The problem is ... It works like this ... It costs ... In DBO ..., or as an idea ... I can go deeper on any part."

The seven steps clock

For "design X" questions. Steps 1 to 5 are short on purpose. The deep dive gets the most time.

Say this: "First I will agree the scope, then size it, then the API and data, then one picture, then go deep on the hardest part, and end with what can fail."

When you do not know

Never a bare "I don't know". Four short steps instead.

Say this: "I have not used it directly. What I know is ... so my best guess is ... because ... I would check it by ..."

Always a number

86,400 seconds a day, call it 100,000 · peak is 2 to 3 times average · 99.9% is about 43 minutes down a month · 3 retries at 3 layers is 27 calls · Snowflake ids: 4,096 per millisecond per machine · Lambda: 15 minutes, 10,240 MB, 6 MB request.

Always a cost

Cache: speed, but stale data. Replica: more reads, but lag. Shard: more writes, but no joins across shards. Queue: fast request, but repeats and later results. Microservices: separate deploys, but network failures and more work to run.

DBO facts you may say as facts

Four services (API with GraphQL, Prisma and Nexus; Auth with OTP and JWT; Queue with BullMQ on Redis; Cron) · three Postgres databases split by owner (auth, queue, toko) · CapRover on Docker Swarm · TADA, Manager and Jatis by webhooks and HTTP · the double refund from duplicate TADA webhooks, fixed with SELECT ... FOR UPDATE · you led the team.

Everything else is an idea

Outbox, sagas, read replicas, CDN, PgBouncer, unique event ids, OpenTelemetry for DBO: say "an idea I would add", never "we built".
