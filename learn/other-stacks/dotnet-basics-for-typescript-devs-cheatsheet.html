.NET for a TypeScript Dev

Your Skyworx.Kredit.Api, explained in your own language

Every card is a C# ↔ TypeScript pair. Tick the circle when you can explain it out loud.

1

.NET = runtime + stdlib + CLI

The CLR runs compiled C#. ASP.NET Core is the built-in web framework. One install, batteries included.

In TS: Node.js + npm + Express, but the framework ships with the platform.
2

C# = TypeScript, compiled

Static types like TS, but they are not erased — types exist at runtime. var is inference, not any.

In TS: strict mode, except the type checker also runs in production.
3

.csproj + NuGet

The .csproj file lists dependencies and build config. NuGet is the package registry. bin/ and obj/ are build output.

In TS: package.json + npm + dist/.
4

Program.cs shape

Always: builder → register services → Build() → order middleware → Run(). Registration and pipeline are separate phases.

In TS: index.ts with app.use() and app.listen(), but Express mixes both phases.
5

Controller = router class

[Route("api/[controller]")] maps PengajuanKreditController to api/pengajuankredit. [HttpGet("{id}")] marks an action.

In TS: an Express Router; [HttpGet("{id}")] ≈ router.get("/:id").
6

ActionResult returns

Ok(x), NotFound(x), NoContent(), CreatedAtAction(...) — you return the response instead of writing to it. CreatedAtAction builds the Location header for you.

In TS: res.status(200).json(x), res.status(404).json(x), res.status(204).end().
7

Model binding

Typed parameters are filled automatically: Guid id from the route, DTO from the JSON body. Malformed UUID = automatic 400 before your code runs.

In TS: req.params + req.body, but parsed, typed, and validated for you.
8

DTO vs entity

Entity = DB shape. DTO = API contract. Clients cannot set Id or CreatedAt — mass-assignment protection built into the design.

In TS: GraphQL input types vs the Prisma model — same separation, same reason.
9

Dependency injection

Register in Program.cs, declare in the constructor, the container delivers. Never new a dependency. Tests pass fakes straight into the constructor.

In TS: import prisma from "./db" — Node's module cache is your implicit container.
10

Lifetimes: Singleton / Scoped / Transient

One forever / one per HTTP request / new every resolve. DbContext is Scoped: stateful + not thread-safe, so it must not be shared across requests.

In TS: module import / res.locals-style per-request value / calling a factory each time.
11

DbContext + DbSet

KreditDbContext is the DB gateway; DbSet<PengajuanKredit> is the typed table handle you query with LINQ.

In TS: PrismaClient and prisma.pengajuanKredit — but scoped per request, not a singleton.
12

OnModelCreating = schema in code

Fluent config maps classes to tables: ToTable, HasColumnName, HasColumnType, HasIndex. Your UTC value converter normalizes DateTime on every read/write.

In TS: schema.prisma — @@map, @map, @db.Decimal, @@index.
13

EF migrations

dotnet ef migrations add X diffs model vs snapshot and writes C# Up()/Down() methods. dotnet ef database update applies them.

In TS: prisma migrate dev --name x — Prisma writes SQL, EF writes C# that makes SQL, with rollback included.
14

Change tracking — the big shift

Load an entity, mutate its properties, call SaveChangesAsync(). EF diffs against original values and UPDATEs only changed columns. There is no update() call in your PUT.

In TS: Prisma is explicit — update({ where, data }). EF watches; Prisma is told.
15

Validation via data annotations

[Range(0.01, ...)] on the DTO + [ApiController] = automatic 400 with field errors before the action runs. Gotcha: [Required] on decimal does nothing — a missing field becomes 0, so Range(0.01, …) is the real guard.

In TS: a zod schema + a validate middleware — here the pipeline is the middleware.
16

Middleware = onion

Class with InvokeAsync(HttpContext); await _next(context) passes the request on. First registered = outermost, so the exception handler goes first.

In TS: app.use with next() — but Express puts the error handler LAST; .NET puts it FIRST. Both mean outermost.
17

ILogger<T> + Serilog

ILogger is the built-in abstraction (T = category). Serilog is the implementation with sinks: your app writes to Console + a daily rolling file.

In TS: pino / winston; sinks ≈ transports.
18

Message templates, not interpolation

"error on {Method} {Path}" stores Method and Path as queryable properties. String interpolation melts them into text — searchable only by regex.

In TS: logger.error({ path }, "msg") in pino — pass objects, never concatenate.
19

JWT: AddJwtBearer + [Authorize]

TokenValidationParameters checks signature, expiry, issuer, audience. UseAuthentication fills HttpContext.User; [Authorize] rejects with 401. Claims = payload fields (Sub, Jti).

In TS: jwt.verify + an Express auth middleware; HttpContext.User ≈ req.user.
20

Task ≈ Promise, but threads

Same async/await model, different engine: thread pool vs event loop. .Result blocks a thread and can deadlock — Node cannot even express that mistake. Rule: async all the way down.

In TS: Task<T> ≈ Promise<T>; there is no ".Result" in JS — and that is a feature.
21

decimal vs double — money

double = IEEE 754 float = JS number (0.1 + 0.2 problem). decimal = exact base-10, 28–29 digits. Your entity uses decimal for plafon, bunga, angsuran — deliberate, because it is money.

In TS: number is always double; Prisma Decimal wraps a library to get what C# has natively.
22

LINQ ≈ filter / map / sort

Where / Select / OrderBy / FirstOrDefault. On a DB query it compiles to SQL, like Prisma; on a List it runs in memory, like array methods.

In TS: .filter().map().sort().find() — with SQL translation when aimed at the database.
23

xUnit + your test isolation

[Fact] ≈ test(); [Theory] + [InlineData] ≈ test.each. Each test builds an InMemory DbContext named with a fresh Guid — isolated, parallel-safe.

In TS: Jest with a fresh in-memory DB per test; WebApplicationFactory ≈ supertest for real-pipeline tests.
24

appsettings.json = config home

Connection string, JWT settings, log levels. Environment variables override it at runtime. Secrets belong in env vars or a secret manager in production.

In TS: .env + a config module — with layered overrides built in.

Both sides visible. The verdict is what you say in the meeting.

decimal vs double MONEY
decimalExact base-10, 28–29 digits. Stored money, rates, anything a bank audits. Maps to Postgres numeric.
doubleFast binary float ≈ JS number. Fine for math helpers like Math.Pow where sub-rupiah error is acceptable.
Verdict: decimal for every stored money value (your entity does this). Double only inside the annuity formula, rounded to 2 decimals at the end — and say the production fix is a decimal pow + explicit MidpointRounding.
Scoped DbContext vs Singleton PrismaClient LIFETIME
DbContext → ScopedStateful change tracker, not thread-safe. One per request = clean unit of work, disposed automatically.
PrismaClient → SingletonStateless query gateway with an internal connection pool. Safe to share app-wide.
Verdict: not a contradiction — lifetime follows state. Saying this sentence proves you understand both ORMs.
Controllers vs Minimal APIs STRUCTURE
ControllersClasses + attributes, conventional validation and filters. The enterprise standard; scales with many endpoints and devs.
Minimal APIsExpress-style route handlers on app. Microsoft's 2025 default for new small services; .NET 10 added annotation validation.
Verdict: you chose controllers — right for a CRUD API with auth + validation, and the style a banking codebase already uses.
Data annotations vs FluentValidation VALIDATION
AnnotationsZero setup, per-field rules on the DTO, automatic 400 via [ApiController]. Covered everything the spec asked.
FluentValidationRules as testable code; cross-field and DB-aware checks — like zod .refine().
Verdict: annotations first; add FluentValidation when a rule touches two fields — e.g. validating angsuran against plafon, bunga, and tenor.
await vs .Result ASYNC
awaitFrees the thread back to the pool while waiting. Async all the way down — what your code does everywhere.
.Result / .Wait()Blocks a thread; can deadlock when the continuation needs that same thread; starves the pool under load.
Verdict: never .Result in request code. Bonus line: "Node can't even express this mistake — the event loop has no blocking wait."
InMemory unit tests vs WebApplicationFactory TESTING
InMemory + direct controller callsFast, isolated (fresh Guid-named DB per test), parallel-safe. But skips auth, validation, binding.
WebApplicationFactoryBoots real Program.cs in memory ≈ supertest. Asserts 401 without token, 400 on bad Range. Add Testcontainers for real Postgres.
Verdict: own the gap before they ask — "my unit tests don't exercise the pipeline; the upgrade is WebApplicationFactory plus Testcontainers."

Mnemonics — plain-words meaning included.

Room service DI

The constructor is the order card; the container delivers to your room. You never go shopping (never call new) for dependencies yourself.

Onion pipeline

First registered = outermost layer. The exception handler is the onion's skin. Express peels from the other end — its error handler goes last. Both mean: be outermost.

EF is a proofreader, Prisma is dictation

EF keeps the original, you edit the draft, it finds the differences (change tracking). Prisma makes you spell out every change (explicit update).

decimal counts on fingers, double rounds in binary

Base-10 vs base-2. Money always counts on fingers — that is why plafon, bunga, and angsuran are decimal.

Scoped follows state

DbContext holds per-request state → per-request lifetime. PrismaClient holds none → singleton. Lifetime follows state.

Builder, then pipeline

Program.cs in five words: builder → services → build → middleware → run. Registration is "what exists"; the pipeline is "what runs, in what order".

Authentication asks who, authorization asks whether

AuthN parses the JWT and fills User; authZ checks [Authorize] against it. Who must come before whether — that is why the order is fixed.
