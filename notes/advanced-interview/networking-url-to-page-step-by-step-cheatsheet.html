URL TO PAGE NETWORKING CHEATSHEET

13 steps. 3 round trips. Know what breaks at each one.

The five pictures to draw. Practice each in under 30 seconds while saying the line under it.

1 · The whole journey in 13 steps

Say this: "Parse, check local caches, DNS, then TCP, TLS and HTTP. On a cold connection that is about three round trips plus DNS, then the server works, then the browser renders."

2 · The DNS walk

Say this: "The browser asks its resolver once. On a cache miss the resolver walks root, then .com, then the authoritative server, and caches the answer for the TTL. There are 13 root names but 2,045 instances worldwide, thanks to anycast."

3 · Three round trips: TCP, TLS 1.3, HTTP

Say this: "TCP is one round trip. TLS 1.3 is one more. The first byte of the response arrives after the third. At 180 ms that is over half a second, so I cut round trips with reuse, TLS 1.3, HTTP/3, and a CDN close to the user."

4 · Inside the server side

Say this: "A cache hit at the edge never reaches my servers. A miss goes through the load balancer, which usually ends TLS, to a stateless app that reads Redis or Postgres. A 502 means a backend broke the connection. A 504 means it was too slow."

5 · From HTML bytes to pixels

Say this: "The main thread builds the DOM, styles, layout and paint records. Other threads raster and composite. CSS blocks painting and plain scripts block parsing, so I use defer, keep critical CSS small, and preload the LCP image."

All visible. RTT = round trip time. 20 ms is a CDN in your city. 180 ms is a far origin, such as Jakarta to the US East Coast.

Do not guess. Find which step failed, then run the matching command.

# 1. DNS - the full walk from the root down
dig +trace shop.example.com

# 2. Does the site advertise HTTP/3 in DNS?
dig HTTPS example.com

# 3. Time of every stage in one line
curl -o /dev/null -s -w 'dns:%{time_namelookup} tcp:%{time_connect} tls:%{time_appconnect} ttfb:%{time_starttransfer} total:%{time_total}\n' https://example.com

# 4. Which protocol? Is HTTP/3 advertised?
curl -sI --http2 https://example.com | grep -iE '^(HTTP|alt-svc)'

# 5. TLS version, certificate chain, cipher
openssl s_client -connect example.com:443 -servername example.com -tls1_3 -showcerts </dev/null

# 6. The route packets take
mtr -rw example.com

# 7. Watch handshake packets (needs sudo)
sudo tcpdump -i any -n 'tcp port 443 and host example.com'
How to read the curl line: every value is cumulative from the start. tcp − dns is the TCP handshake. tls − tcp is the TLS handshake. ttfb − tls is the request plus the server's own time. The biggest gap is your problem. Chrome DevTools, Network tab, Timing panel shows the same breakdown per request.
