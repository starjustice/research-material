Java & Spring for a TypeScript Dev

Everything mapped back to what you already know

Every card is a Java ↔ TypeScript pair. Tick the circle when you can explain it out loud.

1

JVM = the runtime

You write .java, it compiles to bytecode, the JVM runs it. Types are real at runtime — that's why annotations can do so much magic.

In TS: types are erased when compiled to JS. In Java they survive.
2

Maven / Gradle = npm

pom.xml (Maven) or build.gradle lists dependencies. Packages land in a shared ~/.m2, not per-project.

In TS: package.json + node_modules — but node_modules is per project.
3

Type comes first

String name = "x"; not let name: string. final means const. var infers, but only for local variables.

In TS: name: string = "x". Same idea, reversed order.
4

Numbers are not one type

int, long, double, BigDecimal. Money always uses BigDecimal — double is binary floating point and drifts.

In TS: one number type for everything. In C# you met decimal — BigDecimal is its twin.
5

== vs .equals()

== compares references for objects. .equals() compares content. Use Objects.equals(a,b) for null safety.

In TS: === just works on strings. In Java it silently returns false.
6

Everything is in a class

No top-level functions. A standalone helper becomes a static method on a class.

In TS: export function foo() at file top level is normal. Not allowed here.
7

record = data holder

record Account(String number, BigDecimal balance) {} auto-generates constructor, getters, equals, hashCode, toString. Use for DTOs.

In TS: type Account = { number: string; balance: number }.
8

No union types

There is no string | number. Use an enum for fixed values, a sealed interface for one-of-these-shapes, or method overloading.

In TS: unions are everywhere. This is the feature you will miss most.
9

Streams = array methods

list.stream().filter(x -> ...).map(...).toList(). Arrow syntax is identical. Order::getAmount is a method reference.

In TS: arr.filter(...).map(...) — same shape, extra .stream() and .toList().
10

null only, plus Optional

No undefined. Optional<T> makes absence explicit: .map(), .orElse(), .orElseThrow().

In TS: null | undefined and optional chaining ?. — Java has neither.
11

Checked exceptions

The compiler forces you to catch or declare throws for checked ones (IOException). Unchecked (RuntimeException) behave like JS errors.

In TS: no equivalent at all. Every error is unchecked.
12

Spring Boot ≈ NestJS

Decorators become annotations. @RestController, @Service, @Repository. Dependency injection works almost the same.

In TS: @Controller(), @Injectable() in Nest. You already know this model.
13

JPA ≈ Prisma, different philosophy

JPA tracks loaded entities. Change a field inside @Transactional and it saves on commit — no explicit update call. Called dirty checking.

In TS: Prisma makes you call update() explicitly. JPA is implicit.
14

Repository from method names

findByStatusAndAmountGreaterThan(...) — Spring generates the SQL from the method name. No body needed.

In TS: you write the Prisma where clause yourself.
15

@Transactional

Wraps the method in a DB transaction. Rolls back on unchecked exceptions by default. Skipped if you call the method from inside the same class.

In TS: prisma.$transaction(...) — explicit rather than annotation-driven.
16

Virtual threads

Since Java 21: write simple blocking code that scales to millions of tasks. The JVM's answer to async, without colouring every function.

In TS: async/await everywhere. Java gets the scalability without the syntax.

Left is what you know. Right is the same thing in Java.

  | "PENDING"

    PENDING, APPROVED, REJECTED

Array methods → Streams

TypeScript
const names = users
  .filter(u => u.active)
  .map(u => u.name);

const total = orders
  .reduce((s,o) => s + o.amount, 0);
Java
List<String> names = users.stream()
    .filter(u -> u.isActive())
    .map(u -> u.getName())
    .toList();

BigDecimal total = orders.stream()
    .map(Order::getAmount)
    .reduce(BigDecimal.ZERO, BigDecimal::add);
Arrow syntax is the same. Order::getAmount is a method reference — shorthand for o -> o.getAmount().

Collections

TypeScript

You declare the interface (List) and instantiate an implementation (ArrayList).

Absent values

TypeScript
const name = user?.name ?? "Unknown";

if (user) { ... }
Java
String name = maybeUser
    .map(User::getName)
    .orElse("Unknown");

maybeUser.orElseThrow(
    () -> new NotFoundException("no user"));
No optional chaining. NullPointerException is Java's "cannot read property of undefined".

The three layers

Say this: "Business logic saya taruh di Service, bukan di Controller. Controller cuma menerjemahkan HTTP ke objek dan sebaliknya." Interviewers check for exactly this.

An endpoint, side by side

Express
app.get("/api/loans/:id",
  async (req, res) => {
    const loan = await svc
      .findById(req.params.id);
    if (!loan)
      return res.status(404).json(...);
    res.json(loan);
});
Spring Boot
@RestController
@RequestMapping("/api/loans")
public class LoanController {

  private final LoanService svc;

  public LoanController(LoanService svc) {
    this.svc = svc;   // constructor injection
  }

  @GetMapping("/{id}")
  public ResponseEntity<LoanResponse> get(
      @PathVariable Long id) {
    return svc.findById(id)
      .map(ResponseEntity::ok)
      .orElse(ResponseEntity.notFound().build());
  }
}

The tradeoffs and traps that separate a mid answer from a senior one.

MONEY BigDecimal vs double
BigDecimalExact decimal arithmetic. Verbose: a.add(b), not a + b.
doubleFast, simple syntax. Binary floating point — 0.1 + 0.2 ≠ 0.3.
Verdict: money is always BigDecimal. In a bank, a fraction of a cent of drift breaks reconciliation. Same instinct as decimal in C#.
NULLS int vs Integer
intPrimitive. Cannot be null. Use when the value always exists.
IntegerObject wrapper. Can be null — needed for nullable DB columns.
Verdict: a nullable column maps to Integer, not int. And == on two Integers compares references — use .equals().
ERRORS Checked vs unchecked exceptions
CheckedCompiler forces catch or throws. IOException, SQLException.
UncheckedNo obligation. Extends RuntimeException. Like all JS errors.
Verdict: modern teams prefer unchecked for business errors — checked clutters every signature and encourages empty catch blocks. Spring's DataAccessException is unchecked for exactly this reason.
JPA LAZY vs EAGER fetching
LAZYLoads related data on first access. Default and usually right.
EAGERAlways loads relations. Over-fetches on every query.
Verdict: keep LAZY, but watch for N+1 — 100 loans + reading each customer = 101 queries. Fix with JOIN FETCH or @EntityGraph. Same problem you solved with DataLoader in GraphQL.
DI Constructor vs field injection
ConstructorExplicit, can be final, trivially testable with mocks.
Field @AutowiredLess code. Hides dependencies, hard to test.
Verdict: constructor, always. This is a common interview question — the answer is testability and immutability.
CONCURRENCY Virtual threads vs reactive
Virtual threadsWrite simple blocking code, scale to millions of tasks. Java 21+.
Reactive (WebFlux)Non-blocking throughout. Powerful but hard to read and debug.
Verdict: virtual threads for most new work — same scalability, far simpler code. Say: "kode blocking sederhana bisa scale seperti async."

The Java questions most likely to come up, with the answer shape.

Apa bedanya == dan equals()?

== compares references for objects and values for primitives; equals() compares content. Always equals() for objects. Follow-up they love: if you override equals() you must override hashCode(), or the object misbehaves in a HashMap or HashSet.

Kenapa BigDecimal untuk uang, bukan double?

double is binary floating point, so decimal fractions like 0.1 aren't exact and errors accumulate. BigDecimal is exact decimal arithmetic. In banking, drift of a fraction of a cent breaks reconciliation.

Checked vs unchecked exception?

Checked must be caught or declared — compiler-enforced. Unchecked extends RuntimeException, no obligation. Modern practice leans unchecked for business errors because checked clutters signatures. Spring made DataAccessException unchecked for this reason.

Kenapa constructor injection, bukan field injection?

Dependencies become explicit and can be final. Testing is far easier — pass mocks straight into the constructor, no reflection. Field injection hides dependencies and makes the class hard to instantiate in a test.

Apa itu N+1 di JPA, dan solusinya?

With LAZY fetching, relations load on first access — 100 loans then reading each customer produces 101 queries. Fix with JOIN FETCH in a @Query or an @EntityGraph so it becomes one query. Same class of problem as GraphQL N+1, solved by batching.

Apa itu @Transactional?

Wraps the method in a DB transaction — all writes commit or roll back together. Two details worth adding: it only rolls back on unchecked exceptions by default, and because it works via a proxy, calling the method from inside the same class silently bypasses it.

Bagaimana menangani race condition?

Use your real story: two concurrent requests both passed the "already processed?" check before either committed → double points. Fixed with row-level locking (SELECT ... FOR UPDATE) so check and write are atomic. Then the senior line: "lock di JVM cuma berlaku di satu instance — untuk sistem multi-instance, lock di database atau distributed lock yang tepat."

Anda dari Node/TypeScript — apa yang paling berbeda?

Different: checked exceptions, no union types, everything inside a class. Similar: OOP, generics, and dependency injection — Spring is very close to NestJS. And you already learned C# from zero for an assessment, so the jump is a short one.

"Type first, then name"

The single syntax habit to rewire: String name, not name: string. Everything else follows from reading a few files.

"Controller thin, Service fat"

Controllers translate HTTP. Services hold business logic. Repositories touch the database. If logic creeps into a controller, an interviewer notices.

"JPA saves without save()"

Inside @Transactional, changing a loaded entity writes on commit — dirty checking. This surprises every Prisma developer exactly once.
