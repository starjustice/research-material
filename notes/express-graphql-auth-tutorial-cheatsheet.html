1 · One authenticated GraphQL request, end to end

Say this: "The context function is GraphQL's auth middleware. It verifies the JWT signature once per request — no DB read — and puts userId in context. Resolvers then decide access; ownership is enforced in the Prisma WHERE clause, never filtered afterwards in JS."

2 · Login, then refresh with rotation

Say this: "Refresh tokens are single-use. Each refresh deletes the old row and issues a new pair, so a stolen token that gets replayed finds nothing. RFC 9700, the 2025 OAuth security BCP, made rotation the standard."

3 · JWT anatomy — three parts, one dot between each

Say this: "Base64 is encoding, not encryption — never put secrets in the payload. The signature only proves the server issued it and nobody edited it. Because I can't revoke it, I keep it at 15 minutes and pair it with a revocable refresh token."

4 · deleteNote — the two gates, in order

Say this: "Authentication and authorization are two different questions with two different error codes. requireUser answers 'who are you' — 401. The ownership check answers 'may you' — 403. I keep them separate on purpose."

The whole GraphQL auth pattern in ~12 lines. If you can write this from memory, you can rebuild the app.

// once per request — GraphQL's "auth middleware"
const context = ({ request }) => {
  const h = request.headers.get("authorization") ?? "";
  const t = h.startsWith("Bearer ") ? h.slice(7) : null;
  return { prisma, userId: t ? verifyAccessToken(t) : null }; // bad token → null, no throw
};

// the gate, called inside protected resolvers
function requireUser(ctx) {
  if (!ctx.userId) throw new GraphQLError("Not authenticated.", {
    extensions: { code: "UNAUTHENTICATED", http: { status: 401 } },
  });
  return ctx.userId;
}

// ownership lives in the QUERY, never filtered afterwards in JS
prisma.note.findMany({ where: { authorId: requireUser(ctx) } });
How to talk about it: "Context identifies, resolvers authorize. Context never throws so login and register work anonymously. Registration catches Prisma's P2002 unique-constraint error instead of find-then-create — the DB constraint wins the race two simultaneous signups would cause. And login returns one identical error for bad email and bad password, so nobody can enumerate accounts."
