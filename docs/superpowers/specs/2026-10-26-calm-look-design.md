# Calm look for the Study Hub: design

Date: 2026-10-26. Status: approved. Phases 1 to 4 are built (see "Result" at the end). Phase 5 (lesson content) is still the owner's call.

## Why

The owner often loses interest when a page is mostly text, then stops reading and learns nothing. They learn from pictures and analogies, in short pieces. Their own words: "easy to understand, interesting way to explain, image or analogy, not long paragraphs."

A new look cannot make text shorter. It can make a page easier to scan, easier to start reading again, and nicer to press. So the work has two parts: the look (this document) and the lesson content (later, Phase 5).

## What the owner decided

- **Look:** "B Calm", picked from three mockups. Dark 2px borders, a small hard shadow, soft colors, rounded 12px corners, colored boxes for each kind of content, buttons that press down.
- **Fonts:** Lexend for body text, Space Grotesk for headings. The owner compared Lexend, Atkinson Hyperlegible Next and DM Sans on a real lesson and chose Lexend.
- **Style source:** neobrutalism.dev, as inspiration for the look.
- **First test:** one lesson, Database lesson 01. The test worked (see "Spike result").

## My calls (please check these)

- **Copy the look, do not adopt the library.** neobrutalism.dev is React + Tailwind + shadcn components. The site is plain HTML pages on GitHub Pages. Adopting the library means rebuilding the whole site in React or Next.js. Copying the look into one CSS file does not.
- **Look first, default later.** The viewer keeps its `&look=calm` switch until the owner says go. The other page types have no switch: the owner reviews them on the local preview before the change goes to `main`.
- **Keep dark mode wherever it exists today** (hub, study route, cheatsheets). The viewer has none today, so it gets one only if the owner asks.
- **Fonts from Google Fonts**, as `study.html` already does.

## Goals

1. Every page type has the Calm look, so the site feels like one product.
2. One shared `calm.css` replaces about 100 separate inline copies, so a later change is one edit.
3. Text is more comfortable to keep reading: font, size 16px, line spacing, and each lesson section shown as its own card.

## Non-goals

- No rebuild in React, Next.js or Tailwind.
- No rewriting of lesson content in Phase 1 to 4.
- No new features (accounts, saving progress to a server).

## Anti-goals (a failure even if it technically works)

- It looks nice but the lessons are still walls of text.
- A stepper stops working, or a diagram stops rendering.
- Pages get hard to use on a phone, or scroll sideways.
- A page that has dark mode today loses it.
- Colors that carry meaning in a stepper (for example stack = blue, freed = red) change meaning.

## Spike result (Database lesson 01)

Built in `calm.css` and `viewer.html`. It turns on with `&look=calm` in the address. Without it, nothing changes.

It works: 13 section cards with colored headers, 6 of 6 diagrams render, answers open as pressable bars, no sideways scroll on a phone, no console errors, and the choice stays on while moving between lessons.

The spike also found two problems that exist on the live site today:

1. **Placeholder bug.** The lesson template has lines like `<write here>`. The markdown reader treats them as HTML tags, and they swallow the rest of the page (the Review questions and Connected lessons sections). 61 lesson files have this. The spike escapes them only in Calm mode.
2. **Wide diagrams are tiny.** A left-to-right diagram with 7 boxes shrinks until the text cannot be read.

## Phases

Each phase ends with a checkpoint: the owner opens 2 or 3 pages and says go.

- **Phase 0 (done):** the spike above. Approving this document keeps the spike code as the starting point for Phase 1.
- **Phase 1, lessons:** make Calm the default in `viewer.html`. Fix the placeholder bug for everyone. Make wide diagrams readable (scroll sideways, or tap to enlarge). Check four lessons from different subjects and one long one, on desktop and phone.
- **Phase 2, hub and speak:** change the CSS inside `scripts/build-hub.py`, then run `python3 scripts/build-hub.py`. Restyle `speak.html`. Keep the hub's dark mode.
- **Phase 3, steppers (62):** let `calm.css` cover the shared classes. Add one `<link>` per page with a small script. Keep each stepper's own meaning colors. Click through Next in a sample from every subject.
- **Phase 4, cheatsheets (32):** merge the two `sheet.css` copies into one, give all 32 the Calm look, keep dark mode where it exists. (The 15 inline pages keep their own CSS; see "Result".)
- **Phase 5, lesson content (a separate design, the owner's call):** shorter pieces, more pictures and analogies, predict-and-reveal inside lessons. This is the part that fixes "long paragraphs".

The Study Route (`study.html`) was added after Phase 4. The owner asked for the whole site, so it was unified.

## How we know a phase works

For each page type: open it in a browser at desktop width and at phone width. No sideways scroll, no console errors, diagrams render, stepper buttons work, dark mode still works where it existed. While a page type is opt-in, the plain address must look exactly as before.

## Constraints

- GitHub Pages serves the site under `/research-material/`. A link like `/calm.css` would break there. Use relative paths (`../../../calm.css` from a nested page).
- Work on `main` and merge worktree work back (the repo's own rule). Preview locally with the `static-hub` entry in `.claude/launch.json`.
- Plain, simple English in anything the owner reads.

## Left to the builder

Exact dark colors, class names, how the script adds the link to 62 pages, whether to host the fonts ourselves, and shadow size on small screens. Also how `calm.css` wins where a page's own inline CSS disagrees (scope it under a body class, or load it last). The rule is: the Calm look wins on look, and the page keeps its own colors where they carry meaning.

## Result (2026-10-26)

Built with `docs/superpowers/plans/2026-10-26-calm-look-phases-2-to-4.md`. Every page type now uses `calm.css`:
hub, record page, 62 step-by-step pages, 32 cheatsheets, study route, and the lesson viewer from Phase 1.

- **One file, sections per page type.** Shared tokens use a `calm-` prefix (`--calm-line`, `--calm-edge`, ...). The first try used plain names and broke the code lab, which already defines its own `--line` as a color.
- **Meaning colors are untouched.** Checked on all 62 step-by-step pages by comparing the color of every kind of element before and after: only the buttons, tabs, top links and the "Predict first" box changed.
- **Dark mode kept.** Pages with their own dark mode get the class `can-dark`, so Calm swaps its outline and soft box colors too.
- **Inline cheatsheets kept.** The 15 cheatsheets with inline CSS were not merged into `sheet.css`: they use different variable names and have no dark mode. The risk was higher than the gain. They only gained `calm.css`.
- **A guard test** (`tests/calm-pages.test.js`) fails for any new page without the Calm look, and for any new kind of page that no group covers.
- **Phone fixes found on the way:** `08-classes` and `14-observability` scrolled sideways, and 7 of 8 sampled study route notes did (a long command chip could not wrap). All fixed.
- **Known minor:** on a 375px phone one metric tile in `14-observability` hangs about 10px past its panel border (still on screen).

## Phase 5 trial: Database lesson 01 in short cards (2026-10-26)

The owner said yes to a trial on one lesson before changing the other 60. The lesson file was rewritten in place (the old version is in git at `e2ad0fd`). Nothing else changed except one small rule in `calm.css`.

**The shape of a card.** Every card is one idea and starts with a picture or an analogy. Then the owner guesses, then presses an orange bar (`<details class="guess">`) to see the answer. Each card ends with one `> **Remember:**` line. The text outside the answer bars stays near 100 words.

**What changed in the lesson.**

- The wall of pictures in section 2 is gone. Each picture now sits inside the card that needs it.
- The "Common mistakes" section became three cards (a new name in WHERE, `= NULL`, LIMIT without ORDER BY). Each one is problem first, then a guess, then the fix.
- Cards 1 to 7 hold about 510 words outside the answer bars (about 780 with the answers). The old main path was about 1,500 words.
- Kept as they were: the stepper, the links, the interview answer, "Explain it back" (the record button still appears), review questions. The Go deeper boxes moved to one last card.
- The practice "fix the bug" now has three bugs in one query, so it tests all three cards together.

**Rules found on the way (for the other lessons).**

- Use `graph TB`. A left-to-right picture is too wide on a phone. To stack two separate flows in one picture, join them with `~~~` (an invisible link).
- Keep picture labels short. A branching graph with three answers was 376px wide on a 375px phone, so it became a three row table.
- Keep code lines near 36 characters. Put comments on their own line above the code. A comment at the end of a line was cut off and hid the step numbers.
- Emoji in picture labels render fine (the librarian picture).
- The viewer needs no code change. Each H2 is already a card. Only a `details.guess` color rule was added.

**Checked.** Every SQL block was run on PostgreSQL 17.5 (PGlite) and the results match the lesson. All 5 pictures render. No sideways scroll at 375px and 1100px, no console errors, 23 tests pass.

**Known.** The 4 column orders table is 337px wide on a 375px phone, so it swipes (the open "tables on phones" decision). The big-table examples in the Go deeper box (`stores`) were carried over from the 2026-10-16 check and not re-run.
